该项目的错误处理采用**分层、多范式混合**的设计，客户端与服务端各自遵循不同的约定，但整体保持一致的“错误码”思想。

## 1. 客户端（Qt）：基于 `ErrorCodes` 枚举与信号/槽的错误传播
- 核心定义位于 `client/llfcchat/include/global.h` 中的 `enum ErrorCodes`，包含 `SUCCESS=0`、`ERR_JSON=1`、`ERR_NETWORK=2` 等基础状态码。
- HTTP 模块通过 `httpmgr.h` 暴露 `sig_http_finish(ReqId, QString, ErrorCodes, Modules)` 等信号，将请求结果连同错误码一起以 Qt 信号/槽机制传递给 UI 层。
- TCP 文件传输在 `filetcpmgr.cpp` 中监听 `QTcpSocket::error` 信号，根据 `QTcpSocket::SocketError` 枚举分支处理连接拒绝、远程关闭、主机未找到、超时等网络错误，并通过 JSON 字段 `"error"` 解析服务端返回的业务错误码。
- UI 层使用 `qDebug()` / `qWarning()` 输出调试信息，并在关键路径（如图片加载失败）调用 `QMessageBox::critical` 弹出错误对话框。

## 2. 服务端（C++ 微服务）：Boost.Asio 异步错误码 + MySQL 异常捕获
- 所有 C++ 服务端（ChatServer、GateServer、ResourceServer、StatusServer）均在各自的 `include/const.h` 中定义独立的 `enum ErrorCodes`，涵盖 JSON 解析失败、RPC 失败、验证码过期/错误、用户已存在、密码错误、邮箱不匹配、Token 失效、UID 无效、文件操作失败、Redis 读取失败等场景。
- Boost.Asio 异步 I/O 统一通过 `boost::system::error_code` 参数传递底层错误，例如 `HandleAccept(shared_ptr<CSession>, const boost::system::error_code & error)`、`asyncReadFull(..., std::function<void(const boost::system::error_code&, std::size_t)>)`、`HandleWrite(..., const boost::system::error_code& error, ...)`。
- MySQL 访问层（`MysqlDao.h`）直接捕获 `sql::SQLException`，在连接池初始化、健康检查、重连等路径打印 `std::cout << "..." << e.what() << std::endl` 形式的日志，并尝试自动重建连接。
- 各服务间通过 gRPC 调用时，若下游 RPC 失败则设置 `reply.set_error(ErrorCodes::RPCFailed)`，由上层统一判断。

## 3. 通用工具：`Defer` RAII 清理
- 每个服务的 `const.h` 都包含一个轻量级的 `Defer` 类，用于在作用域结束时自动执行资源释放逻辑（如归还连接、解锁），避免异常路径下的资源泄漏。

## 4. 设计决策与约定
- **错误码集中化**：每个模块/服务独立维护 `ErrorCodes` 枚举，便于按领域划分错误语义。
- **异步优先**：服务端完全基于 Asio 的 `error_code` 回调风格，不抛出 C++ 异常；客户端依赖 Qt 的信号/槽和 Socket 错误信号进行错误传播。
- **异常仅用于基础设施**：MySQL 驱动异常被捕获并转换为可恢复的逻辑（重试/重连），业务层不依赖异常流控制。
- **日志即诊断**：大量使用 `qDebug()/qWarning()/std::cout` 作为错误定位手段，未见结构化日志框架。

## 5. 开发者应遵循的规则
- 新增错误码时，先在对应模块的 `const.h` 或 `global.h` 中扩展 `ErrorCodes` 枚举，保持命名一致（如 `Error_Json`、`RPCFailed`）。
- 服务端异步回调必须检查 `boost::system::error_code` 参数，不可忽略；数据库操作必须包裹 `try/catch (sql::SQLException&)`。
- 客户端 UI 层通过信号/槽接收 `ErrorCodes`，禁止在 UI 线程中直接处理底层网络异常。
- 使用 `Defer` 管理临时资源，确保异常安全。
- 对外暴露的错误信息应简洁明确，避免泄露内部实现细节。
