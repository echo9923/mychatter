模块以 `imt` 命名空间组织，按职责划分为四层，依赖方向单向：
- 基础设施层：`im_common.h` 集中声明端口/消息 ID/错误码常量与全局失败计数器 `g_failures`，并通过 Pass/Fail/Check 宏输出 `[PASS]/[FAIL]` 格式；`im_frame.h` 提供 TCP/JSON 帧编解码（仅依赖 nlohmann_json）。
- 外部依赖封装层：`im_http_client.*`（Boost.Beast 同步 HTTP）、`im_tcp_client.*`（带后台 reader 线程的 TCP 帧收发器）、`im_mysql.*`（mysql-concpp 封装）、`im_redis.*`（hiredis 封装），每个类提供 Connect/Close 生命周期与 connected() 状态查询。
- 进程编排层：`im_harness.*` 通过 Win32 Job Object + CREATE_SUSPENDED + AssignProcessToJobObject 拉起各 Server 可执行文件，为每个服务生成独立 `config.ini` 并轮询 ready_port 确认就绪；INI 生成函数 MakeStatusIni/MakeChatIni/MakeGateIni/MakeResourceIni 镜像生产配置布局但重定向到测试端口。
- 场景层：`im_scenarios.*` 实现四个确定性用例，每个 Scenario*() 函数自行创建 ProcessManager/Redis/Mysql 并在退出时清理 footprint，场景之间无耦合。
入口由 main() 驱动，通过 Failures() 返回值决定退出码。
