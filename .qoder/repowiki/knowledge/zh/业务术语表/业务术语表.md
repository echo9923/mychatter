### Gate Server（网关服务）
- 定义：项目的 HTTP 网关服务，负责处理客户端的注册、登录、重置密码等短连接请求。作为外部请求的统一入口，验证用户身份后通过 gRPC 调用 Status Server 获取负载最低的 Chat Server 节点地址，并返回给客户端。
- 别名：网关服务、Gateway

### Chat Server（聊天服务）
- 定义：基于 Boost.Asio 实现的 TCP 长连接服务，负责实时消息转发、好友申请/认证、文件传输等核心聊天功能。支持多实例部署，通过 Redis 实现分布式锁和会话管理。
- 别名：聊天服务器、ChatServer

### Status Server（状态服务）
- 定义：服务发现与负载均衡服务，管理所有 Chat Server 节点的在线状态和负载信息。当 Gate Server 需要分配 Chat Server 时，Status Server 根据各节点的连接数选择负载最低的节点。
- 别名：状态服务、StatusServer

### Resource Server（资源服务）
- 定义：专门处理大文件和图片传输的服务，支持分片上传、断点续传、进度显示等功能。每个分片带序列号，传输进度持久化到 Redis，断线重连后可从上次位置继续传输。
- 别名：资源服务、ResourceServer

### Verify Server（验证服务）
- 定义：独立的 Node.js 邮件验证码派发服务，负责生成和发送邮箱验证码。通过 gRPC 接口被 Gate Server 调用，验证码存储在 Redis 中并设置过期时间。
- 别名：验证服务、VarifyServer、验证码服务

### 分布式锁
- 定义：基于 Redis 的分布式锁实现，使用 `SET key uuid NX EX timeout` 命令确保多节点环境下的互斥访问。应用于用户登录、注册等并发场景，防止同一用户的重复操作导致状态混乱。
- 别名：Redis分布式锁、分布式互斥锁

### 踢人机制
- 定义：用户异地登录时的旧连接清理机制。如果用户在另一台 Chat Server 上已经登录，当前服务器会通过 gRPC 通知目标服务器执行踢人操作，确保单点登录。同服直接内存踢除，跨服通过 RPC 通知。
- 别名：踢下线、异地登录处理

### 心跳保活
- 定义：客户端定期发送心跳包维持连接活跃性的机制。Chat Server 每 60 秒扫描一次所有 session，如果超过 20 秒无数据交互则判定连接断开，清理 session 并释放 Redis 中的登录状态。
- 别名：心跳检测、连接保活

### 最小连接数负载均衡
- 定义：根据各 Chat Server 当前有效连接数进行负载分配的算法。每台 Chat Server 定时上报连接数到 Redis，Status Server 在被查询时选择连接数最少的节点返回给 Gate Server。
- 别名：负载均衡、连接数均衡

### 断点续传
- 定义：大文件传输中断后能够从上次断点继续传输的技术。每个文件分片带序列号，传输进度（seq、已传大小）持久化到 Redis，客户端重连后携带上次 seq 请求续传，避免重复传输。
- 别名：断点续传、分片续传

### 粘包处理
- 定义：解决 TCP 字节流协议中多条消息粘连问题的技术方案。自定义应用层协议，消息头固定 6 字节（2字节 msg_id + 4字节 data_len），采用"先读头、再读体"的两阶段异步读取策略。
- 别名：粘包拆包、消息边界处理

### WebRTC 音视频通话
- 定义：基于 WebRTC 技术的实时音视频通信功能，集成 coturn 穿透服务和自研信令服务器，支持 P2P 音视频通话。信令服务器负责交换 SDP 和 ICE 候选信息。
- 别名：音视频通话、WebRTC视频
