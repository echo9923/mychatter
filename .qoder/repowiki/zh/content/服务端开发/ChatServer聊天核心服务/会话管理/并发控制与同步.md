## 项目结构
本项目在服务器端包含多个服务进程（如 ChatServer、ResourceServer），每个服务均实现基于 Boost.Asio 的会话模型 CSession，负责网络 I/O、读写协议解析、消息入队与异步发送。不同服务的 CSession 实现略有差异，但并发控制模式一致：通过互斥锁保护发送队列与关闭操作，通过 shared_ptr 与 enable_shared_from_this 管理对象生命周期，通过异步回调维持非阻塞高吞吐。

## 核心组件
- CSession：封装单个 TCP 连接的完整生命周期，包括读头/体、写队列、心跳检测、异常处理与清理。
- 发送队列与锁：_send_que 与 _send_lock 保障多生产者单消费者式异步写入的线程安全。
- 会话级锁：_session_mtx 用于保护连接关闭等关键操作。
- 共享指针管理：继承 enable_shared_from_this，通过 SharedSelf() 和 lambda 捕获 self/shared_self 确保回调期间对象存活。
- 心跳与过期检测：原子时间戳记录最后接收时间，提供 IsHeartbeatExpired/UpdateHeartbeat。
- **新增** 原子关闭机制：_close_after_send 标志配合 SendAndClose 方法确保最终帧的原子发送和有序关闭。
- **新增** 三阶段关机序列：LogicSystem::Stop() 实现入口拒绝、逻辑处理排空、跨服投递排空的有序停机。

## 详细组件分析

### 互斥锁与临界区：_session_mtx 与 _send_lock
- _send_lock：保护发送队列的入队、出队与触发异步写。所有 Send 重载与 HandleWrite 均在持锁状态下访问 _send_que，避免竞态。
- _session_mtx：在 Close 中使用，确保 socket 关闭与状态标志更新是原子的，防止并发读取/写入时出现悬空或重复关闭。
- **新增** _close_after_send 标志：配合 SendAndClose 方法，在同一把锁内设置关闭标志并入队终帧，确保后续 Send 调用被拒绝。

### 原子发送与优雅关闭：SendAndClose 方法
**新增功能** SendAndClose 方法提供了原子性的最终帧发送和保证 socket 关闭的机制：

- **原子性保证**：在同一把 _send_lock 内先设置 _close_after_send 标志，再入队终帧，确保该帧是最后一帧
- **幂等性保护**：如果已经安排过终帧，重复调用会被忽略
- **有序关闭**：HandleWrite 在发送队列排空后才真正执行 Close，保证错误响应完整写出
- **应用场景**：用于登录失败、服务器繁忙等需要立即关闭连接的场景

```mermaid

participant Sess as "CSession"
participant Q as "发送队列"
participant Net as "网络层"
App->>Sess : SendAndClose(msg, msgid)
Sess->>Sess : 获取 _send_lock
Sess->>Sess : 设置 _close_after_send = true
Sess->>Q : 入队终帧
alt 队列已有正在发送的数据
Sess-->>App : 返回等待 HandleWrite
else 队列为空
Sess->>Net : 发起 async_write(终帧)
end

Net-->>Sess : HandleWrite 回调
Sess->>Q : 弹出已发送项
alt 队列非空
Sess->>Net : 再次 async_write(下一项)
else 队列为空且 _close_after_send = true
Sess->>Sess : Close() 真正关闭连接
end
```

### 三阶段关机序列：LogicSystem::Stop() 方法
**新增功能** LogicSystem::Stop() 方法实现了优雅的三阶段关机序列：

- **第一阶段 - 拒绝新入口**：设置 _ingress_stopping = true，拒绝新的 client/gRPC 请求投递
- **第二阶段 - 排空逻辑处理**：停止所有 logic workers，允许 outbound 跨服投递继续产生
- **第三阶段 - 排空跨服投递**：logic workers 全部 join 后，设置 _delivery_stopping = true，然后停止 delivery workers

这种设计确保了：
- 不会丢失任何待处理的业务逻辑
- 跨服通信能够正常完成
- 系统能够平滑退出而不影响现有连接

```mermaid
flowchart TD
A["调用 Stop()"] --> B["获取 _stop_mutex 锁"]
B --> C{"是否已在停止中?"}
C --> |是| D["直接返回"]
C --> |否| E["设置 _ingress_stopping = true"]
E --> F["停止所有 logic workers (w->Stop())"]
F --> G["设置 _delivery_stopping = true"]
G --> H["停止所有 delivery workers (w->Stop())"]
H --> I["释放锁并返回"]
```

### 共享指针管理与循环引用避免
- 继承 std::enable_shared_from_this<CSession>，并通过 SharedSelf() 暴露 shared_ptr。
- 在异步回调中，lambda 捕获 self（shared_from_this）或显式传入 shared_self，确保回调执行期间对象不被析构。
- 避免循环引用：LogicNode 仅持有 session 与 recvnode 的 shared_ptr，若上层逻辑存在反向强引用需改为 weak_ptr，防止环状引用导致无法释放。

### 异步回调中的对象生命周期：HandleWrite 的 shared_self
- HandleWrite 接收 shared_ptr<CSession> 作为参数，内部再次调用 shared_from_this 获取当前实例，确保即使外部释放了原始指针，回调仍可安全运行。

- 所有对 _send_que 的访问均在 _send_lock 保护下进行，保证"检查长度-入队-触发写"的原子性。

### 死锁预防与锁顺序一致性
- 在错误处理路径中，先获取分布式锁（Redis），再操作线程锁（_mutex/_session_mtx）。若其他路径顺序相反，可能产生交叉锁导致死锁。
- 建议统一加锁顺序或使用 std::scoped_lock 同时获取多把锁，避免 A 拿 m1 等 m2、B 拿 m2 等 m1 的经典死锁。
- **新增** LogicSystem::Stop() 使用独立的 _stop_mutex 保护停机流程，避免与其他锁产生冲突。

```mermaid
flowchart TD
A["路径A: 先分布式锁 -> 后线程锁"] --> OK["顺序一致"]
B["路径B: 先线程锁 -> 后分布式锁"] --> Risk["可能死锁"]
OK --> Safe["安全"]
Risk --> Fix["统一顺序 / scoped_lock"]
```

## 性能考虑
- 锁粒度优化：
  - _send_lock 仅包裹队列操作与一次 async_write 触发，避免长时间持锁。
  - _session_mtx 仅用于 Close 等短临界区。
  - **新增** _close_after_send 标志检查在锁内进行，避免额外的锁开销。
- 减少拷贝：SendNode 构造时尽量使用移动语义，避免大对象复制。
- 背压与限流：MAX_SENDQUE 限制队列长度，防止内存暴涨。
- 异步流水线：HandleWrite 串行推进队列，避免多次并发写竞争。
- **新增** 优雅关机：三阶段关机序列确保系统平稳退出，避免资源泄漏。

## 结论
通过对 CSession 的并发控制机制的系统化梳理，明确了以下关键点：
- 使用 _send_lock 与 _session_mtx 精确划分临界区，确保发送队列与连接关闭的线程安全。
- 借助 enable_shared_from_this 与 shared_self 传递，保证异步回调期间的对象生命周期安全。
- **新增** SendAndClose 方法提供原子性的最终帧发送和优雅关闭机制，确保错误响应的完整性。
- **新增** LogicSystem::Stop() 的三阶段关机序列，实现系统的有序和平滑退出。
- 统一分布式锁与线程锁的加锁顺序，避免死锁；必要时采用 std::scoped_lock。
- 通过队列长度限制与异步流水线提升吞吐与稳定性，结合监控指标持续优化性能。

这些改进显著增强了系统的可靠性和可维护性，特别是在处理异常情况和服务关机时的行为更加可控和可预测。
